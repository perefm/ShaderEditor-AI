# Keyframe animation samples

Two small glTF 2.0 scenes generated by [`generate_keyframe_samples.py`](./generate_keyframe_samples.py)
to exercise the keyframe-animation, scene-camera and Model-info features
(spec [006-keyframe-animation-cameras-model-info](../../../specs/006-keyframe-animation-cameras-model-info/spec.md)).

| File | What it demonstrates |
| --- | --- |
| `KeyframeCube.gltf` | **Animated objects.** Two cubes driven by node keyframes: `OrbitAndSpin` (translation + rotation) and `Pulse` (scale). Pick a clip in the Render panel's *Animation* combo and toggle *Loop animation*. Both cubes share a single mesh referenced by two nodes, which is also the shape Assimp's `aiProcess_FindInstances` produces from identical meshes, so this sample doubles as a regression test that every instance of a shared mesh is drawn at its own node transform. |
| `KeyframeCamera.gltf` | **Animated camera.** A static cube plus an `OrbitCamera` node whose translation/rotation are keyframed. Select `OrbitCamera` in the Render panel's *Camera* combo: `view`, `projection` and `uCameraPos` are then driven by the camera's keyframes every frame. |

Both files embed their vertex and animation buffers as base64 inside the `.gltf`,
so they are self-contained, diffable text and need no sidecar `.bin`.

To regenerate them (output is deterministic):

```sh
python assets/models/KeyframeSamples/generate_keyframe_samples.py
```

## Suggested shaders

Use `assets/shaders/pixel_lighting.glsl` to see the view-dependent specular
change as the animated camera moves — that highlight is what proves `uCameraPos`
is tracking the selected camera rather than the free camera.
